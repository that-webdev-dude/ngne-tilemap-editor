# NGNE Tilemap Editor — Suite, stack and packaging

The tilemap editor is the second tool of the NGNE editor suite. A user who knows
ngne-sprite-editor must recognise this app on sight and use it without relearning. This file
fixes identity, design system, stack, packaging and repo conventions.

**Reference implementation:** ngne-sprite-editor 1.0.0, local checkout
`..\ngne-sprite-editor` at commit `ea5c91d`, written `se/` below. "Copy" means take the file
from `se/` as is; "adapt" means copy and change only what the row states.

## 2. Design system

Copy `se/docs/DESIGN.md` §1–§4 and §8 rules unchanged; this editor's `DESIGN.md` adds its
own panels, tools and viewport chrome.

- **Principles:** neutral grey chrome, the artwork is the only colour; one accent for
  selection, focus and the active tool; 1 px hairlines; no shadows except popovers and
  dialogs; no gradients; canvas first; state always visible.
- **Tokens:** copy `se/src/ui/styles/tokens.css` and its token test. Dark is the default
  (`#0f0f10` workspace, `#18181a` panel, accent `#83e8e1`); light set under
  `[data-theme="light"]`. Only `tokens.css` holds raw colours.
- **Type:** `Inter, "Segoe UI", system-ui, sans-serif`, no web font; 12 px body, 11 px labels
  and status bar, 13 px dialog titles; weights 400 and 500 only; `tabular-nums`.
- **Space and shape:** control height 24, row 28; radii 4 (controls), 6 (popovers, dialogs),
  0 (regions); 2 px accent focus ring on keyboard modality only; motion 100/120 ms ease-out,
  zero under `prefers-reduced-motion`.
- **Icons:** `lucide-react` through the `Icon` wrapper, 16 px, stroke 1.5; no decorative icons.
- **Theme:** dark default, switched in Preferences, stored as `ngne-tilemap-editor.theme`.
- **Primitives and shell:** copy `se/src/ui/primitives/`, `se/src/ui/shell/`, toast, dialog
  host, dock registry, command palette and menu bar.

## 4. Interaction rules

Same as the sprite editor:

- One command registry drives menus, command palette, shortcuts and the shortcut sheet.
  F6 / Shift+F6 cycle regions.
- Tooltips after 400 ms with name and key; every icon-only control has an `aria-label`.
- Toasts: bottom-centre, one line, 4 s; errors and toasts with an action stay. Toast = result
  of a command or an async failure; status bar = transient tool feedback; dialog = a decision
  is needed.
- Dialogs 560 px; large dialogs (import, export, update tileset) 960 px and 86% height;
  primary action accent-filled and right-aligned.
- Confirm only what undo cannot reverse. No context menus on the canvas. Pointer targets
  ≥ 24×24 px. Layouts verified at 1280×720 and 125% browser zoom.
- Overlay chrome: the `*.overlay.ts` layer registry, grid alphas, marching ants, 7 px white
  handles with a black border; zoom and Fit live in the status bar only.

**Shortcuts:** a command both editors have uses the sprite editor's key. Tiled's keys
([reference/tiled.md](reference/tiled.md) §3) are used only for commands the sprite editor
lacks; a Tiled key already bound in the sprite editor gets another key. `DESIGN.md` holds the
full table.

## 6. Architecture and code reuse

Same layering as the sprite editor (`se/docs/SPEC.md` §5):

```text
 ui/ (React panels, dialogs, menus) --dispatches--> app/ (stores, tools, commands, files)
                                                      | executes commands
                                                      v
 core/ (pure TS: map model, undo, terrain solver, compositor, packer, codecs)
        | visible cells, chunk pixels         | packed atlases, tilemap JSON
        v                                     v
 engine/ viewport (WebGPURenderer)       engine/ preview (BrowserGame)
```

- `core/` imports nothing from the DOM, React or NGNE and runs under Vitest in Node.
- `engine/` is the only importer of `@ngne/core`.
- `ui/` changes documents only through registered commands.
- Registries (commands/keymap/menu, dock, overlay, tools, context bar) take a new feature
  without editing shared files.

What is copied from `se/`, file by file, is [DESIGN.md](DESIGN.md) §3: verbatim
(byte-identical, drift-checked), adapted (changed only as listed) and pattern-only rows. The
sprite editor's `src/engine/` is not copied (built on 0.2.1 workarounds); the tilemap editor's
engine layer is new ([ENGINE.md](ENGINE.md)). Copied files are recorded in `docs/PROVENANCE.md`
(created at scaffold) with source path and sprite-editor commit; `scripts/drift.ts` reports
changes in the sprite editor to verbatim files since the recorded commit.

## 7. Packaging and distribution

| Item | Value |
| --- | --- |
| PWA | `vite-plugin-pwa` `injectManifest`, hand-written `src/app/pwa/sw.ts`, `injectRegister: false` — adapt from `se/` |
| Service worker | One cache per deployment (hash of the manifest), cache-first; deletes only caches with its own prefix |
| Updates | Toast "A new version of the editor is ready." with Reload; checks on visibility change and hourly |
| File handling | Manifest `file_handlers` for `.ngtilemap` (`application/x-ngtilemap`), `launch_handler` `focus-existing`; each launched file opens as a project |
| Pickers | Open: `application/zip` with `.ngtilemap`. Import Tileset: `.png`, `.ngsprite` (`application/zip`), `.atlas.json` |
| Hosting | GitHub Pages, `that-webdev-dude/ngne-tilemap-editor`, built with `vite build --base=/ngne-tilemap-editor/`; `deploy.yml` on a `v*` tag or manual dispatch |
| CI (`ci.yml`, push and PR, Node 24) | `check`; E2E in 4 shards plus an `alone` project, headed Chrome under xvfb with SwiftShader WebGPU; golden path ×10; README commands; link check. Budgets report-only |
| Release notes | `CHANGELOG.md`: `## <version> – <date>`, sections per milestone, then Known limitations |
| File formats | Frozen at 1.0.0; any change needs a new version and a migration |
| Ownership | The owner pushes, merges, tags and deploys |

### Storage names

Both apps are served from one origin (`that-webdev-dude.github.io`), so storage is shared
space; every name carries the app prefix.

| Kind | Name |
| --- | --- |
| localStorage | `ngne-tilemap-editor.<key>` |
| IndexedDB | `ngne-tilemap-editor-<name>` |
| Web Locks | `ngne-tilemap-editor-page:<id>` |
| Service worker cache / messages | `ngne-tilemap-editor-<hash>`, `ngne-tilemap-editor:skip-waiting` |
| Project format ID | `ngne-tilemap-project` (file extension `.ngtilemap`) |
| Game format IDs | `ngne-tilemap` (tilemaps), `ngne-sprite-atlas` (tilesets) |
| NGNE texture IDs | `ed:` prefix ([ENGINE.md](ENGINE.md) §3) |

## 8. Repo conventions

- Tickets `TE-0xx`, one branch per ticket named `<prefix>/<description>` with the prefix
  `feat`, `dev`, `cleanup` or `chore`, one commit per ticket with the one-line message
  `[TE-0xx] Title`, the ticket's title unchanged.
- Shared E2E wait helpers exist before the first UI ticket; the suite is sharded from day 0.
